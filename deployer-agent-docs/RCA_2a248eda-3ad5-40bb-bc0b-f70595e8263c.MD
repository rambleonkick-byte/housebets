# RCA — New user shows ~$30,000 balance after a ~200 deposit

**App:** ApexOdds (wager-ledger-4) — FastAPI + MongoDB
**DB read:** `wager-ledger-4-test_database` (read-only, active run `2a248eda-3ad5-40bb-bc0b-f70595e8263c`)
**Status:** Root cause CONFIRMED from production data. No data modified.

## Problem statement
A brand-new user shows a ~$30,000 balance despite depositing only ~200. Hypothesis from E1: the deposit crediting code credits `tx.sent_amount` to the static address's coin and ignores `tx.currency`, so ~200 USDT sent to a SOL address was booked as 200 SOL (≈$30k at ~$150/SOL).

## Did the OxaPay tx currency differ from the address coin?
The stored deposit record does **not** preserve OxaPay's `tx.currency` — the code writes the *address's* coin (`sa["coin"]`), so the raw currency field cannot be read back from Mongo. Strong circumstantial proof it differed:
- The deposit's track_id (153352805) maps to the **SOL/Solana** static address, so funds arrived on the Solana-network address.
- The credited amount is **200.242908**, a USDT-sized number. A genuine 200 SOL deposit would be ~$30k and the user would not describe it as "only 200." The value 200.24 credited 1:1 as a SOL *quantity* is exactly what happens when a ~200 USDT (SPL-USDT on Solana) transfer is booked as SOL.
- Solana USDT (SPL) transfers use the same base58 signature format seen in `tx_hash`, consistent with a USDT transfer over the Solana network to the SOL address.

Conclusion: the user sent ~200 USDT (on Solana) to their SOL static address; `_credit_static_txs` credited `float(tx.sent_amount)` = 200.24 to `sa["coin"]` = **SOL**, ignoring `tx.currency`. Result: 200.24 SOL ≈ $30k instead of ~200 USDT.

## Root cause
Code bug in `_credit_static_txs(sa, txs)`: it credits the transaction amount to the static address's configured coin and **ignores `tx.currency`** (and does not convert by price). Any deposit whose actual on-chain currency ≠ the address coin is credited as the wrong asset at a 1:1 quantity, massively inflating balances when a stablecoin amount is booked as SOL/ETH/BTC quantity.

## Suggested fixes
1. **Code (E1):** In `_credit_static_txs`, compare OxaPay `tx.currency` to `sa["coin"]`. Reject/flag mismatched deposits (or credit to the matching wallet coin / convert by market price) instead of blindly crediting `sa["coin"]`. Also persist `tx.currency` on the `static_deposits`/`transactions` records so mismatches are auditable.
2. **Data correction (production Mongo):** This user's wallet is wrong. SOL 200.242908 reflects a ~200 USDT deposit. After the code fix, correct user 6ad7c9b392ae4680b42af9ef's wallet (e.g. SOL → 0, USDT → ~200.24) and reconcile the deposit/withdraw/refund rows. Audit other accounts for the same pattern (amounts that look like stablecoin values credited as SOL/ETH/BTC).
