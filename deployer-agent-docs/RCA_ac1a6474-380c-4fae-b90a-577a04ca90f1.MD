# RCA — "What happened to the domain I purchased"

## Problem statement
User reports a purchased custom domain and asks whether the recent redeploy (ApexOdds / wager-ledger-4, React + FastAPI + MongoDB) changed or detached it, and whether the live site loads on that domain.

## Investigation & evidence
- `describe_deployment_state`: deployment `wager-ledger-4`, status active, latest run `ac1a6474...` (type=redeploy, trigger=secret_change) **succeeded** at 2026-10-20T15:31:45Z. Default URL `https://wager-ledger-4.emergent.host`. frontend_type=kubernetes.
- `list_domains`: `domains: []` — **no custom domain attached** to this deployment.
- `check_domain_status`: `domains: []` — nothing to DNS-check; no domain linked.
- `preview_health_check` on default URL: **HTTP 200, healthy, 622ms**, serving the real app bundle.

## Root cause
No custom domain is currently linked to this deployment. There is no domain name, DNS record, SSL cert, or route to report because none exists in the deployment's domain bindings.

The redeploy did **not** detach anything. Custom domains are bound at the deployment level, not per deploy-run; a redeploy (and this secret_change-triggered run) rebuilds/rolls the app image and never modifies domain bindings. The code changes (hero carousel, affiliate panel) are UI-only and unrelated. Purchasing a domain at a registrar does not auto-link it to the Emergent deployment — it must be explicitly added and DNS-pointed.

## App health
The app is live and serving correctly on the default domain `https://wager-ledger-4.emergent.host` (200 OK). No app/infra problem.

## Fix (user action)
1. Deployment Panel → Domains → "Link your Domain" → add the purchased domain.
2. At the registrar, create the exact DNS record shown there (verbatim).
3. Wait for verification + SSL issuance to complete; the default URL keeps working meanwhile.
