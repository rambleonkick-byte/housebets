# RCA — "Slider / alt-lines not launched on the update" (wager-ledger-4)

## Problem statement
After deploying the update (alt lines + player props), production `GET /api/odds?league_key=NBA`
reportedly returned only `moneyline/spread/total` — no `alt_spread`/`alt_total`, no `props` —
while the same code in preview returned alt markets. Reporter suspected SGO errors/timeouts
forcing the stale-while-revalidate cache to serve old pre-alt-line data forever.

## What I checked (prod, active run 7992d7e4-813b-45a8-816c-865e62dd3ec0)
1. **Backend logs (SGO health)** — NO SGO errors. Every SportsGameOdds call returns `HTTP 200 OK`
   with `includeAltLines=true` in the query, e.g.
   `GET https://api.sportsgameodds.com/v2/events?...&includeAltLines=true "HTTP/1.1 200 OK"`.
   No `SGO {key} -> {status}` warnings, no `SGO fetch failed`, no 429/401/400/timeout against SGO.
   (The only 429s are to `api.coingecko.com` for crypto prices — unrelated to odds.)
2. **`SPORTSGAMEODDS_API_KEY` secret** — present and non-empty (`is_empty=false`). Not the cause.
3. **`db.odds_cache` (14 docs)** — inspected `ts`/`ttl` and `data[].markets[].market` per league:
   - **Freshly-refreshed docs (ts ≈ 1792531790–1792531930) all contain `alt_spread`+`alt_total`
     (+ populated `props`)**: NBA, NCAAF, NHL, IT_SERIE_A, LA_LIGA, FR_LIGUE_1, UEFA_CHAMPIONS_LEAGUE.
   - **Older docs (ts ≈ 1792531638–1792531667, ~4–5 min old) carry NO alt markets** — every game is
     `moneyline/spread/total` only: NFL, EPL, BUNDESLIGA, MLS. These are carryover documents written
     by the PREVIOUS code version (which did not request alt lines).
   - The NBA doc specifically (ts 1792531810) **does** contain `alt_spread`, `alt_total` and a full
     `props[]` array.
4. **Live endpoint probe** — `GET https://wager-ledger-4.emergent.host/api/odds?league_key=NBA` →
   `200`, and the response body now includes the `alt_spread` ("Alternate Spread") market. **NBA has
   self-healed.**

## Root cause (proven)
This is a **stale-while-revalidate cache-staleness lag after a shape-changing deploy — NOT an SGO
failure and NOT a stuck cache.**

`fetch_sgo_league` reads a **per-pod in-memory cache (`_SGO_CACHE`)** first and only falls back to
`db.odds_cache` when the key is absent in memory. `get_odds` calls it with `max_age=None`, so the
logic is: if `age < ttl` → return the cached doc **verbatim with no refresh**; only once `age > ttl`
(ttl=300s) does it kick a background refresh.

Immediately after the update, each freshly-booted pod loaded the league docs that were persisted by
the OLD code (no `includeAltLines`, so no alt markets/props). While those docs were still inside
their 300s TTL, the endpoint returned the old pre-alt-line shape and did **not** refresh. As each
league's doc crosses its 5-minute TTL, the first request refreshes it via SGO (`includeAltLines=true`)
and alt lines + props appear. NBA (and NCAAF/NHL/soccer leagues) have already rolled over; NFL, EPL,
BUNDESLIGA, MLS were still inside the stale window at inspection time and will populate on their next
TTL expiry. The symptom the user saw was this transient per-league/per-pod lag, now resolved for NBA.

(The reporter's "served forever" worry comes from the error branch that sets `ttl:30, data:prev` on
an SGO non-200/exception. That branch is NOT firing here — all SGO responses are 200. Note it does
have a minor latent weakness: on a pod whose `prev` is empty, an SGO error caches `data:[]` for 30s —
consistent with the empty `NCAAB` doc — but that self-heals in 30s and is not the reported issue.)

## Suggested fixes
- **User / verify:** NBA already returns alt lines + props (verified on the live URL). Hard-refresh /
  re-request. The remaining leagues (NFL, EPL, BUNDESLIGA, MLS) self-populate within ~5 min as their
  300s TTL rolls over. No secret, tier, or infra action needed.
- **Code (E1) — recommended, optional:** eliminate the post-deploy staleness window for shape-changing
  updates. Options: (a) clear/invalidate `db.odds_cache` (and the in-memory `_SGO_CACHE`) on startup/
  version bump, (b) version the cache key/schema so old-shape docs are ignored, or (c) do an eager
  refresh on boot instead of serving a within-TTL stale doc. Also consider: on the SGO-error branch,
  avoid persisting an empty `data:[]` when `prev` is empty.
