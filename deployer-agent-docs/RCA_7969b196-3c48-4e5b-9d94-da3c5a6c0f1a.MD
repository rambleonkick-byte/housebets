# RCA — Withdrawal "Approve & send" shows Cloudflare 520

**App:** https://apexodds.io (deployment wager-ledger-4)
**Active run:** 7969b196-3c48-4e5b-9d94-da3c5a6c0f1a (redeploy, status success)
**Endpoint:** POST /api/admin/withdrawals/{wid}/approve
**Symptom:** Admin clicks "Approve & send" → browser shows Cloudflare 520 "The origin web server returned an invalid or incomplete response". Other admin actions work.

## Verdict
This is **not** a crash, OOM, worker death, hang, or infra failure. The backend handler ran to completion exactly as designed. OxaPay **rejected the payout** because the withdrawal's destination address is invalid/a contract address. The handler then correctly refunded the player and raised **HTTP 502**, and Cloudflare re-renders that origin 502 as a generic **520** page — which hides the real message.

## Evidence

### (a) Backend pod logs during the approve request
Exact OxaPay rejection line (WARNING):
```
WARNING:apexodds:OxaPay payout rejected: 400 {'data': {}, 'message': 'There was an issue with the submitted data. Please verify your input and try again.', 'error': {'type': 'invalid_request', 'key': 'invalid_address', 'message': 'The specified address is invalid or is a contract address. Please check and try again.'}, 'status': 400, 'version': '1.0.0'}
```
Matching access log for the same request:
```
INFO: 172.68.195.194:0 - "POST /api/admin/withdrawals/bf1a045d-a080-406e-80e4-a30e857444dc/approve HTTP/1.1" 502 Bad Gateway
```
- No traceback, no worker crash, no OOM, no container restart tied to the request. The OxaPay exception path was fully caught and handled — exactly as the code description states.
- Note: the 503 Readiness/Liveness/Startup probe failures in pod events are all at 06:56–06:58 (new pods coming up during this run's rollout). Both pods are now `ready:true`, `restart_count:0`. They are startup noise and are unrelated to the approve request at ~06:59.

### (b) Production secrets
- `OXAPAY_PAYOUT_API_KEY` — present, non-empty.
- `OXAPAY_MERCHANT_API_KEY` — present, non-empty.
- There is **no** secret named `OXAPAY_API` — it is a code-level base-URL constant, not an env var. It is working correctly: OxaPay returned a well-formed JSON error (`status:400, version:1.0.0, type:invalid_request`), which proves the request reached and authenticated against the OxaPay payout endpoint and failed **only** on address validation. A wrong URL or bad key would surface as a connection error or 401, not an address-validation 400.

### (c) Prod DB `withdrawals` collection (db: wager-ledger-4-test_database)
The approved withdrawal resolved cleanly — no stuck "approving":
```
id: bf1a045d-a080-406e-80e4-a30e857444dc
coin: USDT  network: ERC20  amount_usd: 589
address: 0x7c7A0ea93f2b040fAfEf085138B5A5784bc7B553   <-- rejected by OxaPay (invalid / contract address)
status: failed   refunded: true   refunded_at: 2026-10-24T06:59:14Z   track_id: (none)
decided_by: admin@apexodds.io
```
The find_one_and_update → _submit_payout → on-failure refund + status "failed" path all executed. No withdrawals are stuck in "approving". Other rows are normal (pending_approval, confirmed with track_id, rejected).

### (d) 502 → 520 mapping
The app itself returned **502 Bad Gateway** (the handler's `raise HTTPException(502, ...)` carrying OxaPay's message). Cloudflare receives that unexpected origin 5xx and presents it to the browser as a **520**, swallowing the JSON body. So the 520 the admin sees is this app's own 502, and the true cause is the OxaPay `invalid_address` rejection above. Other admin actions don't call OxaPay, so they never hit this path — which is why only "Approve & send" fails.

## Root cause
The destination address `0x7c7A0ea93f2b040fAfEf085138B5A5784bc7B553` on withdrawal bf1a045d is rejected by OxaPay as "invalid or is a contract address." The handler surfaces this business/validation failure as HTTP **502**, which Cloudflare masks as a 520 and strips the message — so the admin sees a generic origin error instead of the real reason.

## Fixes
1. **Code (E1):** Don't raise a 5xx for an OxaPay business/validation rejection. Return a **4xx (e.g. 422 or 400)** from `admin_approve_withdrawal` with OxaPay's `error.message` in the body. A 4xx is passed through by Cloudflare, so the admin sees "The specified address is invalid or is a contract address" instead of a 520. (Not reproduced in sandbox — requires the live OxaPay API, which the eph pod cannot reach — but proven by the logs + DB above.)
2. **User (admin/player):** This specific payout cannot be sent to `0x7c7A0ea93f2b040fAfEf085138B5A5784bc7B553` — OxaPay flags it as invalid/a contract address. The player must supply a valid, non-contract ERC20 address (or the admin should reject the request). The player's balance was already auto-refunded, so no funds were lost.
